# Instructions that have an adopter edit a file an upstream merge will change

**Priority:** P2 · **Status:** open
**Found by:** the adopter-merge-friction sweep, 2026-11-16 (`fix/adopter-merge-friction`), after a first adopter's
second upstream merge hit two of them.

## The class

An adopter takes keel by fork and takes updates by merge (ADR-0013). Anything upstream edits, an adopter
should not edit, or every later merge conflicts there. Two cases were fixed in `fix/adopter-merge-friction`: the
path gate failing on a merged-in doc that cites `apps/starter`, and `scripts/check-demo-size.mjs`'s header
asking the adopter to record budget changes in it. This note lists the instructions found by the same sweep
that were NOT fixed, because each needs a decision. "Keel-owned" means a file upstream merges touch: anything
under `packages/keel`, `scripts/`, `docs/`, `.claude/`, the root configs, `CLAUDE.md` and `README.md`.

## The largest one is not an instruction

`pnpm init-app --eject-showcase` rewrites path citations in about 60 docs and generalizes about 16 more. Every
later upstream edit near one of those lines is a merge conflict, and adoption manufactures them all on day one.
Since `fix/adopter-merge-friction` the path gate no longer needs the rewrite for citations of `apps/showcase` and
`apps/starter` (it treats them as keel's when the app is absent), so `init-app` could leave those citations as
written. The cost: an adopted `CLAUDE.md` would still send an agent to `apps/showcase`, which is keel's
reference app and not in the tree, where today it says `apps/<app>` or the survivor's name. That trade is the
decision to make; the numbers above came from running `init-app` on a scratch copy.

## What done looks like

Each row decided, and the ones that stay open moved to their own file. Nothing here is a bug in a gate: every
gate is green in an adopted tree, which is why the class only shows up at the second merge.
